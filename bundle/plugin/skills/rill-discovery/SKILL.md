# Rill Discovery

Use this entrypoint before Rill-controlled research and grill-with-docs workflows that **change product scope or design**.

1. Discover the current repository, relevant GitHub Issues, exact product scope and targeted PRD requirements. Do not re-open previously decided owner questions.
2. Invoke the installed `brainstorming` Skill **once** for this design decision. If upstream platform behavior or standards matter, research original official docs and empirical checks before treating an option as valid.
3. Use `grill-with-docs` only for consequential unresolved design tradeoffs; minimize prompts and avoid repeating the same interview in two skills. Favor a concrete recommendation and only ask for owner input when it changes product outcome.
4. Resolve inconsistencies between brainstorm, research, verified upstream behavior and this project's Constitution. A suggestion is not an approved requirement.
5. Update the current matching PRD acceptance in place after a legitimate decision. Create native GitHub tickets and blockers for implementation; do not duplicate historical prose in PRD.
6. Hand implementation to official Codex roles and the project's delivery skill. Do not execute destructive or protected actions without separate permission.

Ordinary typo fixes, well-scoped repairs, mechanical refactors and already-approved implementation do **not** need a new brainstorming interview. The original `brainstorming` SKILL.md is preserved alongside this orchestration wrapper; any source-referenced optional files absent from the user's upload must be resolved or the affected optional branch disabled before claiming fully functional packaging.
