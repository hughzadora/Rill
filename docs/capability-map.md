# Rill — Codex capability map

Updated: 2026-10-22. Purpose: connect the owner's engineering workflow to official Codex capabilities and Matt Pocock skills without creating a second runtime.

**Authority:** [kernel](policy.md) > [rebuild plan](../rill-rebuild-plan.md). This map is an evidence-index and task router, not another policy source. Consult [upstream engineering facts](rebuild/foundation-inputs.md) before relying on any version-sensitive interface.

## Interpretation

- **Codex:** official host, workspace, instructions, native tools, execution, review and permissions.
- **Matt skills:** engineering method selected for the task, not a substitute for platform actions or authority.
- **GitHub:** native execution record (Issues, dependencies, commits, PRs and reviews); repository Markdown holds specifications.
- **Capability state:** _documented_ means an official source describes it; _available_ means a local interface was observed; _verified_ means the actual workflow ran and its result was checked. Do not treat these states as equivalent.

## Owner context and execution boundaries

The [kernel owner contract](policy.md#21-owner-context-and-priorities) governs all routes: part-time non-developer, budget/agility first inside safety and correctness, GitHub Free private baseline, minimal owner interruption and maintained upstream naming. Use real native multi-agent threads with the kernel's bounded concurrency and single-writer rule; no role-play or custom orchestration. Each job carries a distilled question, candidate revision, write scope and verifiable result; send summaries rather than full traces.

A fresh ordinary task in official Codex CLI 0.163.0 on macOS has executed native design, implementation and non-author review without a delegation reminder. Native `config/read` confirmed project-layer loading of [`.codex/config.toml`](../.codex/config.toml), including the two-thread limit; rejection of excess concurrent work is a separate untested boundary. This CLI evidence does not establish macOS App UI behavior. Native choice UI is available but has not been exercised on a genuine missing decision. Native `account/rateLimits/read` has returned a point-in-time account-window snapshot; this is separate from App usage UI acceptance. Paid private-repository branch protection/rulesets, required human review teams and mandatory remote CI/CD are **out of scope**, not missing acceptance gates.

## Configured native roles

The [development workflow](../.agents/skills/development-workflow/SKILL.md) dispatches the role names defined in `.codex/agents/*.toml`. Each role file contains its explicit model/effort, narrow instructions, capability reductions and compact result contract. The primary remains responsible for owner communication, integration, the index and remote delivery. Planner, worker and non-author reviewer are sequential dependencies; explorer is optional. Keep at most two active delegates, reuse the appropriate role for corrections and let native V2 residency management unload eligible completed tasks.

The owner's requested tuning uses Luna/medium for exploration, Luna/high for bounded implementation and Sol 6.1/medium for design and independent review. Every child requests low verbosity and no reasoning summaries, performs only the assigned task and returns one compact result/evidence/blockers packet. These are output controls and behavioral instructions, not a zero-token guarantee or a separate permission sandbox. Native role identity, actual model/effort and message history must be inspected before claiming application; evidence is recorded under [#6](https://github.com/hughzadora/Rill/issues/6).

This design adopts narrow triggers, isolated task context and summary-only returns from [Claude Code's official subagent guidance](https://code.claude.com/docs/en/sub-agents), using [Codex's supported fields](https://learn.chatgpt.com/docs/agent-configuration/subagents). Claude-specific `tools`, `disallowedTools`, `permissionMode`, `maxTurns` and `effort` frontmatter are not Codex configuration keys. Codex roles inherit parent sandbox/approval/provider/MCP settings. Do not copy an unsupported field or claim that a read-only instruction is hard isolation.

## Non-goals and selection rules

The map does **not** prescribe installing every skill, configuring hooks automatically, building custom orchestration, duplicating GitHub state, using every available tool, or claiming that a skill invocation enforced a policy.

Pick the smallest applicable native path for a real task. Where a native interface cannot support a demanded guarantee, revise or drop that requirement under the kernel; document the gap and do not implement a compatibility layer.

Persisted child histories contained only final result packets, with zero interim agent messages. The optional `explorer` profile was parsed but was not needed or executed in this task. - **Unavailable here:** macOS App UI observation. Account-window percentages and reset timestamps are available through the native read-only API, but are time-specific, shared account values rather than task cost or savings. Remaining App surface acceptance is tracked in issue #4.
