# Domain docs

Rill uses a single-context layout. Before exploring the codebase or deciding domain terminology, read the root `GLOSSARY.md` and relevant decisions in `docs/adr/` when present.

Use glossary terms in issue titles, implementation discussions, and test names. Record new terms and architectural decisions through `/domain-modeling` when they are settled. If a proposal conflicts with an existing ADR, cite that ADR and surface the conflict for review.
