# Rill Software Factory: Agent Entry

Rill is a reusable versioned software-delivery standard for many new and existing repositories, **not** one business product or a substitute harness. Preserve correctness, reproducibility, security and upstream-native practices. Start from actual Git/HEAD and authoritative GitHub task facts, never an unverified chat summary.

Read the relevant portions of [README](README.md), [PRD](PRD.md), [ARCHITECTURE](ARCHITECTURE.md), [PROJECT_MANAGEMENT](PROJECT_MANAGEMENT.md), [HANDOFF](HANDOFF.md), [MULTI_AGENT](MULTI_AGENT.md) and [QUALITY_STANDARD](QUALITY_STANDARD.md). The current engineering parent is [#22](https://github.com/hughzadora/Rill/issues/22), the permanent bug parent is [#23](https://github.com/hughzadora/Rill/issues/23). Update native child issue **bodies** and PRs, not issue comments; preserve older closed issues as evidence.

Codex owns sessions, compaction, native agents, permissions and approvals. Apply the **complete applicable** source gates for React/Tailwind, Node/TypeScript, Python and Shell with established tools, Google engineering practice, Modern Web Guidance and Impeccable; fixtures alone do not certify real products.

Large work: requirements -> clickable prototype -> interactive design -> agent coding with existing regressions -> integration/owner trial -> deep clean and new tests -> full regression, independent reviewer and owner click -> PR. Small work can combine stages without weakening necessary gates. HTML is a visual status and design surface; only real Harness structured selection and protected approval bind consequential decisions.

A handoff must identify the exact candidate, source path, executed checks and logs, reviewer findings, unresolved failures and next safe action. Configuration is not observed execution. Preserve unrelated work. No fabricated evidence, paid fallback, unapproved merge or production changes.
