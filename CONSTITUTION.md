# Rill Constitution

> Standing product intent and decision hierarchy. This document is intentionally separate from the single living product specification in [PRD.md](PRD.md). It defines **why** Rill exists, not a second backlog or an implementation status ledger.

## Mission

Rill is a maintainable, reusable, native-first **software factory** for both new and existing product repositories. An owner describes outcomes, essential product decisions and exceptional protected authorization; established tools and independent agents research, design, implement, test, diagnose, review, recover and deliver genuine working software.

Success is not a beautiful repository scaffold, a green fixture, or an agent's written report. Success is a **released, installable capability** that carries real software work from intent through independently verifiable acceptance in a separate product repository, and survives fresh-agent takeover without copying Rill development conversations.

## Non-negotiable principles

1. **Upstream and native first.** Use official Codex/ChatGPT harness capabilities, Git/GitHub, maintained language tooling and published standards. Do not re-create an agent runtime, scheduler, session transcript store, approval/permission subsystem, or parallel project tracker.
2. **Owner's role stays small.** Owner handles initial intent, consequential product choice, meaningful UX acceptance and protected authorization. Agents own ordinary investigation, implementation, repair, quality checks and coordination.
3. **Truth is evidence-bound.** Distinguish specification, configured capability, locally executed tests, hosted CI, observed native lifecycle, independent review, actual external adoption, owner acceptance and release. Record the exact candidate SHA or artifact version. Unknown is never PASS.
4. **Preserve real work.** Detect and respect existing product code, user-owned configuration, histories and uncommitted changes. No blanket wipe, silent overwrite, destructive reset, forced push or unauthorized merge/deployment. Use native versioned upgrade and verified recovery.
5. **Independent verification.** Mechanical assertions and real runtime checks take precedence over prose. Review is genuinely separate from implementation, including the actual candidate and relevant failure cases; prompts do not substitute for sandbox/permission boundaries.
6. **Quality without theater.** Full **applicable** native tests, security, licensing, accessibility, source inventory and negative cases must be executed. Do not weaken thresholds, game coverage, skip source roots or mistake decorative governance files for enforcement.
7. **Bounded resources.** Respect existing plan/tool quotas, limit retries, parallelism and unattended execution. No paid fallback, credits, upgrades or new services without authorization. Use cheap deterministic compute for mechanical work.
8. **Coherent, compact, discoverable design.** One living `PRD.md` per repository specifies current behavior. This constitution is durable intent. Native GitHub Issues/PRs track actionable work, changes and decision history. Git and CI own code and execution evidence. Avoid duplicate DESIGN/ROADMAP/MULTI_AGENT authorities.
9. **Accessible, inspectable interaction.** Show genuine product flows and meaningful operational state in appropriate UI; prefer straightforward CLI and responsive accessible browser views over full-screen terminal spectacle. Native structured choice and approval controls remain authoritative.
10. **Recoverable autonomy.** A new session can discover scope, task dependencies, code revision, tests, outstanding review and next action from authoritative repositories and external records, with no transcript replay or manual owner re-briefing.

## Product boundaries

**Rill owns:** portable native capability distribution; agent workflow composition through supported Skills, Hooks and justified MCP integrations; upstream-aligned project adoption and lifecycle; execution/quality evidence bindings; safe update and rollback; read-only cross-project visibility; repeatable greenfield/brownfield acceptance.

**Rill does not own:** end-product business logic, custom agent runtime, invented sandbox/permissions, fake approval UI, custom Git/task databases, uncontrolled background spend, generic full-screen TUI, automatic overwriting of consumer repositories or a universal imposed open-source governance template.

**Approved v10.0.1 rebuild:** TypeScript 7-first, with only demonstrated Python/Shell adjuncts. Retire all old Rill runtime/code/configuration on the isolated rebuild branch, retaining prior history only as evidence. Do not write compatibility shims or perform legacy migrations. New independent consumer repositories remain protected from unrelated destructive changes.

## Decision and change authority

- This constitution is the stable design intent. A conflict with verified upstream platform security/capability **must be resolved toward reality**; update the spec and record why rather than preserve a false promise.
- `PRD.md` is the only living product/specification ledger. Edit relevant entries **in place** to reflect current decisions and acceptance. Do not append abandoned requirements or chronicle every chat. Keep durable historical rationale in Git/Issues/PRs.
- Agent instructions must read targeted specification sections, not indiscriminately load full histories. Completion status changes require linked code paths **and actual evidence** at the current version.
- Specifications do not confer permission for purchases, destructive operations, new paid services, production actions, merges, or system-level changes.
- Changes to this constitution require an explicit owner decision with a linked Issue/PR and independently checked consequences; ordinary PRD corrections and issue updates do not.

## Factory release acceptance

A reviewed Rill distribution must be installed in **one real new and one real existing independent product repository**, without borrowing Rill development chat instructions. A fresh native agent uses the distributed skills/tools/roles, completes a meaningful feature or bug fix, runs genuine applicable tests (including failures), gets independent review, and produces an evidence-bound PR. Interrupt the session and prove a fresh agent can resume using Git/GitHub and recorded facts. Verify trusted native events, permission controls, upgrade conflict handling and non-destructive rollback. Protected merge/release and actual owner acceptance remain separate authorization states.

No checklist, generated file presence, unit fixture, or dashboard indicator alone can satisfy this acceptance.
