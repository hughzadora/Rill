# Candidate acceptance

Use [Profiles](PROFILES.md) to select the candidate's checks. The blueprint's [gate semantics](../modern-ai-dlc-engineering-master-blueprint.md#13-required-gate-semantics), [stage exits](../modern-ai-dlc-engineering-master-blueprint.md#142-stage-gate-matrix), and [definition of done](../modern-ai-dlc-engineering-master-blueprint.md#144-final-definition-of-done) govern acceptance.

## Qualify the gates

1. Read the [native task contract](../modern-ai-dlc-engineering-master-blueprint.md#4-establish-one-native-task-contract). Compare approved scope with the actual task graph, package/target inventory and discovered files. Include the read-only tooling-contract assertions in `verify`. Run qualification through its own entry point with disjoint test discovery. Match actual native reports to the expected files and targets for both tasks before claiming coverage.
2. When a tool, rule, parser, target, scope, task or workflow changes, follow [qualification triggers](../modern-ai-dlc-engineering-master-blueprint.md#34-qualification-is-triggered-by-change). In a disposable copy with no production credentials, run the exact task on known-good inputs, inject a representative violation for each applicable gate, assert the expected nonzero status and diagnostic, and verify the restored valid case. Exercise missing task/input/rule discovery and composite failure propagation. Keep fault injection, mutation, and generation in separate copies or finish each operation before shared read-only checks begin.
3. For behavior tests, compare executed cases with [suite discovery requirements](../modern-ai-dlc-engineering-master-blueprint.md#85-test-discovery-and-evidence-completeness). Audit skipped/focused cases, assertions, timeouts, parser errors, and coverage gaps. A failed setup supplies a blocker or a failure under the blueprint's [result definitions](../modern-ai-dlc-engineering-master-blueprint.md#12-results-that-may-be-reported). A negative case is evidence when the intended gate rejects its fault for the expected reason.

## Verify the exact candidate

1. Inspect the [actual change](../modern-ai-dlc-engineering-master-blueprint.md#131-inspect-the-actual-change) against the approved cases and relevant base. Check source, tests, generated outputs, package/artifact contents, policy, ignores, suppressions, and tooling changes. Use the [artifact recipe](../modern-ai-dlc-engineering-master-blueprint.md#113-build-installation-update-and-removal) to exercise each advertised target and consumer lifecycle. For hardening, run the applicable boundary, state failure, mutation, migration, restore, and platform checks from Profiles.
2. Bind `PROJECT_ROOT` to the physical source path, `CANDIDATE_SHA` to the exact committed revision, and `VERIFY_ROOT` to an unused disposable path. Use the [foundation clone recipe](../modern-ai-dlc-engineering-master-blueprint.md#121-complete-the-initial-path-in-order), confirm the detached SHA and clean state, and run [locked setup](../modern-ai-dlc-engineering-master-blueprint.md#33-freeze-and-reproduce-installation) there. For TypeScript + Bun this runs `mise lock --check`, `mise install --locked`, and `mise exec -- bun install --frozen-lockfile`. Before the first commit, label results `UNCOMMITTED` with the exact relevant file digests and keep committed/cold verification pending.
3. Run `mise run verify` and `mise run qualify` separately on the same candidate. Preserve the real tool versions, configs, target lists, diagnostic logs, and process exit statuses. Capture tracked bytes including locks, index identity, and relevant untracked inputs before install and around read-only checks. Compare them after each stage and confirm generated reports are confined to declared outputs. Retain native results and invalidate affected checks after unexpected rewrites, stale reports, or source changes. Keep cache provenance where a valid native cache is used.
4. Run the accepted journey on the verified surface, retain the result, and record the produced artifact digest and consumer results when applicable. Obtain triggered [independent review](#independent-review). If later integration, rebase, squash or merge changes the tested identity, verify and bind the affected evidence to the resulting candidate before acceptance or release.

## Independent review

Use [review triggers and questions](../modern-ai-dlc-engineering-master-blueprint.md#91-changes-that-require-independent-review) for the current change, including verification infrastructure and the final production candidate. Ask a separate agent through an available native Codex delegation or review surface, or use an independent human reviewer. Give them the approved behavior, base and exact candidate, task and target scope, and access to native evidence. Have them read the acceptance source and diff themselves, inspect oracle/discovery changes separately, and run relevant checks or counterexamples as needed under the [semantic checklist](../modern-ai-dlc-engineering-master-blueprint.md#92-concrete-semantic-review-checklist).

Retain the reviewer identity, reviewed revision, findings with references, and dispositions. Fix consequential findings, rerun affected checks and return revised evidence for review. When required review is unavailable, record `BLOCKED` and complete independent work.

## Hosted CI

For configured or approved GitHub hosting, inspect the actual controls using the [GitHub capability recipe](../modern-ai-dlc-engineering-master-blueprint.md#93-github-capabilities-record-the-real-enforcement-boundary). Where controls are unavailable, document the bypassable boundary and preserve applicable CI and independent review.

For an existing or approved GitHub verification workflow with required jobs, apply the [CI aggregation recipe](../modern-ai-dlc-engineering-master-blueprint.md#94-always-aggregate-actual-required-results). Match expected jobs, matrix targets and required events to actual native runs. Verify the always-running aggregate rejects non-success or absent required jobs and observe a run triggered by a change outside ordinary source paths. Record the tested head or merge/queue revision, job links, raw results and the actual required checks, review and branch controls visible on the repository. Local execution, hosted runs and observed platform enforcement have distinct evidence.

## Evidence

Use the current task result and native reports, or the existing issue/PR when one exists. Follow the [required evidence record](../modern-ai-dlc-engineering-master-blueprint.md#141-required-evidence-record).

- Record the user outcome and cases exercised, exact candidate and tree/index state, environment and pinned tooling, config and lock identities, and actual commands with input inventory and exit status.
- Link native logs, test reports and observed journey results. Include the representative fault, expected and observed diagnostic, and safe state for negative runs. Record artifact identity/digest, consumer execution, and independent review and disposition when applicable.
- State remaining limitations, narrowly reviewed exceptions and their reevaluation triggers, and the next incomplete dependency. Label inapplicable, blocked, failed, and unrun gates using the blueprint's definitions. Remove credentials from retained evidence and route failures through the [failure table](../modern-ai-dlc-engineering-master-blueprint.md#143-failure-routing-table).
