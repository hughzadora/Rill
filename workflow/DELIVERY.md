# Rill delivery workflow

Open a workspace created from a versioned Rill template in Codex and say `用 Rill 开始：〈一句话描述想做的产品〉`. For example, `用 Rill 开始：做一个工具，输入购物清单就能算出总价。` Ask `用 Rill 继续` to pick up your work or `用 Rill 验证当前版本` to see whether the current version is ready.

## Start or resume

1. Read the workspace instructions, the current product request, and `docs/PROJECT.md` if it exists. Record the template version from `RILL_VERSION` when supplied. Use the [blueprint workspace classifier](../modern-ai-dlc-engineering-master-blueprint.md#21-resolve-the-target-and-inspect-capabilities) in the authorized directory. Record the physical path, execution capabilities, and Git state. Run subsequent project commands there.
2. For `NO_GIT` or `UNBORN`, follow [initialization](../modern-ai-dlc-engineering-master-blueprint.md#23-initialize-a-new-local-project). For `COMMITTED`, inspect the actual tree, index, worktrees, candidate, manifests, locks, tasks, and reports using [resume inspection](../modern-ai-dlc-engineering-master-blueprint.md#24-inspect-or-resume-a-committed-repository). Preserve existing work. Resolve a wrong parent, corrupt Git state, or inaccessible target before mutating it.
3. Record the user, outcome, first action, expected result, relevant failure, state to preserve, runtime/surface and constraints in `docs/PROJECT.md` as described in [product input](../modern-ai-dlc-engineering-master-blueprint.md#22-establish-the-new-product-input) and [observable acceptance](../modern-ai-dlc-engineering-master-blueprint.md#26-turn-behavior-into-observable-acceptance). Choose routine tools and defaults. If a consequential fact, target identity, or protected authorization is missing, ask one plain-language question with a recommended decision and continue independent work.
4. Select the next stage from the request and observed evidence. For interrupted work, compare the reported candidate with current source and resume at the first incomplete dependency.

## Deliver or verify

| Stage                | Route and exit                                                                                                                                                                                                                                                                                                                                                                 |
| -------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Initialize           | Follow [foundation order](../modern-ai-dlc-engineering-master-blueprint.md#121-complete-the-initial-path-in-order). Use [Profiles](PROFILES.md) to select the required native tools. Add real inputs before binding their tasks. Verify the initial locks and keep results provisional until a real commit and clean checkout exist.                                           |
| Prototype            | Follow [first prototype execution](../modern-ai-dlc-engineering-master-blueprint.md#51-first-prototype-execution). Run the primary journey and consequential failure through its actual surface with disposable data. Record the reproducible command, observed effects, and any simulated boundaries.                                                                         |
| Iterate              | Follow the [iteration loop](../modern-ai-dlc-engineering-master-blueprint.md#52-iteration-loop). For a defect, use the [bug-fix recipe](../modern-ai-dlc-engineering-master-blueprint.md#53-bug-fix-recipe-make-the-causal-claim-testable) and run the same requirement-derived check against the fault and the repair. Demonstrate the change and affected existing behavior. |
| Qualify and accept   | Follow [Acceptance](ACCEPTANCE.md) for locked installation, exact-candidate `mise run verify` and `mise run qualify`, inspection, and triggered independent review. Check the full approved journey against the [stage exits](../modern-ai-dlc-engineering-master-blueprint.md#142-stage-gate-matrix).                                                                         |
| Harden and verify CI | Use [Acceptance](ACCEPTANCE.md) for the supported failure, migration, platform, artifact, and CI checks. Record actual hosted runs and observed merge controls for configured or approved hosting.                                                                                                                                                                             |
| Release or recover   | Follow [Release and recovery](RELEASE.md) when publication, deployment, or recovery is requested, or a released version fails.                                                                                                                                                                                                                                                 |

Report what the user can do, how to try it, what was observed, and any remaining blocker. Use the [blueprint](../modern-ai-dlc-engineering-master-blueprint.md) as the source for activation, requirements, and stage exits.
