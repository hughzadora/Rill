# Release and recovery

## Release

1. Resolve the requested destination and operation. Finish [Acceptance](ACCEPTANCE.md) on the actual release revision, including triggered independent review. If release follows a merge, confirm the resulting revision and refresh affected evidence.
2. Use [artifact qualification](../modern-ai-dlc-engineering-master-blueprint.md#113-build-installation-update-and-removal) and [release bookkeeping](../modern-ai-dlc-engineering-master-blueprint.md#114-release-bookkeeping) to build/package, inspect the artifact, and execute it in a clean consumer on promised targets. Match its digest, public contract, version metadata and notes. Rehearse migration, restore, rollback/forward repair and health/behavior tests wherever relevant using disposable environments.
3. Follow [optional hosting](../modern-ai-dlc-engineering-master-blueprint.md#132-review-and-optional-hosting) for repository operations and [optional publication](../modern-ai-dlc-engineering-master-blueprint.md#133-optional-publication) for package or deployment operations. Use existing authorization. If a protected action needs approval, present the exact source, artifact, destination, effect and recovery plan after completing safe prerequisites. Keep publication separate from build, packaging and checks.
4. After the authorized operation, observe the installed or deployed identity and exercise the accepted journey against that version. Retain the actual version/digest, destination, native operation/run evidence and post-release observations. Route a failed operation or smoke check to recovery and record the observed state.

## Recover

1. Resolve the physical workspace and affected environment. Observe repository/index state, running version, artifact digest and relevant persisted state or migration version. Compare available reports with the current candidate using the [resume procedure](../modern-ai-dlc-engineering-master-blueprint.md#134-continue-interrupted-work-from-observed-state). Resume an interrupted local task at the first incomplete dependency.
2. For a failed behavior, reproduce with sanitized inputs through the actual boundary, preserve unrelated work and data, and use the [bug-fix recipe](../modern-ai-dlc-engineering-master-blueprint.md#53-bug-fix-recipe-make-the-causal-claim-testable) and [failure routing](../modern-ai-dlc-engineering-master-blueprint.md#143-failure-routing-table). Observe durable effects before retrying an operation interrupted near acknowledgement. Rehearse the applicable [failure and state recovery path](../modern-ai-dlc-engineering-master-blueprint.md#103-failure-injection-for-supported-state-changes) in a disposable environment.
3. Use the affected runtime or provider's tested recovery action within the granted authority. For persisted data follow the [engine's rehearsal and restore path](../modern-ai-dlc-engineering-master-blueprint.md#104-database-migration-and-restoration) and verify data invariants and application behavior on recovered state. If production rollback, destructive repair or credential rotation requires authorization, prepare the concrete action and continue safe independent work.
4. Reobserve the running artifact and state, retest the failed journey and affected behavior, and rerun invalidated checks. For a repaired candidate, follow [Acceptance](ACCEPTANCE.md) again for the new revision and review. Report the failure, action taken, resulting source/runtime/data identity, actual checks and any residual impact.
