# Profile routing

## Select and bind

1. Evaluate every row of the [blueprint activation table](../modern-ai-dlc-engineering-master-blueprint.md#31-activation-table) at bootstrap and when capabilities, source languages, interfaces, deployment, or targets change. In the task result, cite the approved behavior and concrete paths or targets supporting each selection. An approved capability awaiting implementation is `NOT RUN`. Use `NOT APPLICABLE` where the activation condition is false and record why.
2. Use [tool ownership and installation](../modern-ai-dlc-engineering-master-blueprint.md#32-tool-ownership-and-installation) to resolve and pin each executable in its owning manifest. Use locked installs after initial resolution. For the first TypeScript + Bun consumer, apply the versioned template in an independent workspace and use the Bun initialization and task recipes below. Select ambient types and runners for the actual application runtime when Bun serves as package manager.
3. Start with the inputs the journey uses. Bind real paths and supported targets in the native manifests, then compose `mise run verify` and `mise run qualify` using the [native task contract](../modern-ai-dlc-engineering-master-blueprint.md#4-establish-one-native-task-contract). Add requirements as their profiles activate. Follow [Acceptance](ACCEPTANCE.md) for discovery, positive and negative runs, and evidence.

## Cross-cutting checks

Use the [control-to-check traceability table](../modern-ai-dlc-engineering-master-blueprint.md#15-concept-to-check-traceability) to close gaps left by a profile name. For actual external boundaries, run [domain and provider contract tests](../modern-ai-dlc-engineering-master-blueprint.md#73-pure-domain-and-external-adapters) and [configuration, input, authorization, privacy and logging cases](../modern-ai-dlc-engineering-master-blueprint.md#102-input-authorization-privacy-and-logging) through the real boundary. For supported writes, inspect state, sentinels, retry and concurrency after [injected failures](../modern-ai-dlc-engineering-master-blueprint.md#103-failure-injection-for-supported-state-changes). For an agreed performance bound, rehearse the same workload and target before and after and retain [diagnostics and measurements](../modern-ai-dlc-engineering-master-blueprint.md#106-diagnostics-and-performance).
