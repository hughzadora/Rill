共享标准与项目事实各有边界

一份共享 SemVer 标准

个人偏好、开发阶段和人工检查点、CI 与修复规则、稳定规则 ID，以及薄原生适配。Matt Pocock 工程方法仍由安装的 skills 提供，不复制进 Rill。

每个项目只记录本地事实

仓库／schema 身份、精确标准版本与摘要、真实工具 argv／版本、明确例外和项目任务事实。例外绑定稳定规则 ID、理由、有限替代／不适用项、owner 来源及复审版本；通配豁免无效，不授予外部权限。

SemVer 2.0.0：1.0 之后 major 表示不兼容、minor 表示兼容新增、patch 表示兼容修复；prerelease 明确标记，build metadata 不影响优先级。0.x 对破坏性公共变化提议升 minor，但仍需显式迁移。版本不自动授权升级，也不能代替行为验收。

每个不可变 release manifest 绑定 SemVer、artifact 摘要与 Git revision、project schema、规则 ID、策略入口、runtime 兼容、hook／MCP 定义和工具能力；沿用现有原生 package/marketplace，插件与标准版本对齐。只有显式兼容条目和行为检查才可支持多个冻结版本；任一已接入项目失去支持时，先阻止 runtime 激活并形成兼容方案。

成功、失败和恢复怎样走

以下保留既有设计的成功、失败与恢复路径。展开可查看前置条件、可机械核实的事实和仍需判断的部分；不是在线模拟，也不会执行命令。历史探针只对应 #18 当时记录的版本与边界，不认证本次源码或替换视图。

正常推进：完整设计先行，按验收切片实现
  1. 读取实际项目、当前任务和既有决定，明确完整范围、核心成功／失败／恢复路径与验收方式。
  2. 用原生交互解决真正缺失的重大决定，记录后再实施依赖变化；完整设计批准后才按依赖切片。
  3. 复用项目工具取得行为证据，持续保存新纠正、修复结果与下一动作；完成标准决定切片是否就绪。

范围缩减必须形成你的决定。Rill 的 skill 仅提供偏好入口，工程步骤使用已有方法。

压缩续接：先保存事实，再核对覆盖
持续记录→原生 PreCompact→原生压缩→SessionStart 指针→来源核对
  1. 压缩前原子保存已同步任务、唯一 outbox、共用约束和 Git 状态；再读取原生历史，历史不可用仍保留基础快照。
  2. 续接先核对仓库／任务／分支／revision／未提交改动，再按指针读来源，核对新纠正、失败及实际资源。
  3. 在线同步权威任务，离线使用此前核对缓存；明确已完成、未完成、未知和下一动作。只暂停依赖缺失要求的变化，独立调查继续。

此前记录的观察

#18 记录过正常信任下手动／自动生命周期、原生历史分页和压缩后的约束／失败状态保留；这些早期观察不等于本批次恢复验收。

验收边界

捕获不自动补出从未记录的语义细项。历史末页、摘要或模型复述不能证明无损恢复；完整细项、超限及负例继续逐项核对。

两轮失败：阻止第三次盲修，取得新证据
原始复现／独立预期→实际修复检查失败 × 2→支持的编辑调用被拦截→新诊断＋解释→下一轮修复

显式 repair-check 保存真实 argv、退出码、日志、候选和环境。连续两次失败后先取得新的区分性诊断证据；换假设、改标题、换聊天或压缩不重置失败历史。重复同候选诊断复用原证据，旧证据不能解锁后续失败。

成功检查保留累计失败；环境或中断未验证不能记为成功。SIGTERM 可观察到子进程结束后保存未知结果；无法捕获的终止保留未完成 lease，需核对原生进程和回执。

hooks 只拦截已支持的原生编辑工具。任意 shell 写入与绕过 hooks 不在此保证内；原因是否成立、问题身份和测试预期是否有效需要工程诊断与独立审查。独立 review/fix 最多三轮，随后重审方案。

断网与冲突：保留两侧，只阻塞受影响工作
  1. 有可靠任务缓存时继续当前授权步骤；新结果以唯一 ID 原子保存，明确待同步。
  2. 联网后核对任务身份、远端范围和本地 outbox；未知写入结果先查 ID，避免重复发布。
  3. 回读不一致、范围变化或关键数据损坏时保留原始材料。先回查来源；只有影响目标或授权且工具无法解决的冲突才用原生选择问你。

任务混淆、未知来源和损坏记录不能被当作成功恢复；本地记录在发布并回读前保留。

发现假完成：撤回结论，回到原验收

先保留原失败、旧 PASS 和原交付事实，撤回无效结论，将受影响验收恢复为未完成或未知。核对批准范围、真实交付端和最终候选；授权允许时重开错误关闭的任务。有效的需求变更和测试修正需要明确契约依据。

只改文档、旧 revision 的绿灯、削弱断言或缺失的实际交付物都不能证明修复。此路径的完整完成判定与纠正接线仍待验收。

阶段和人工检查点来自 #16 真实项目复盘；最新 CI 决定覆盖旧检查时序。阶段可按任务组织合并，完成条件与批准范围保留。

  8. 8 / 单批次 PR

  • commit：Husky 自动只调用 just lint。
  • 开发小步：文案、格式等低风险修改只 lint；行为变化或 bug 修复执行能区分原错误与正确结果的定向检查，按风险而非行数判断。
